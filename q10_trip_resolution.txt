Q10 AMPLIFIER TRIP BLOCKER - RESOLUTION STRATEGY
================================================================================
Date: 2026-09-22
Target Chip: PIC18F47Q10 (Replacing PIC16F18875)
Status: DIAGNOSTIC ACTION REQUIRED

This technical brief isolates the root cause of the immediate "0 keyed runs" 
fault, where the amplifier controller transitions from snoop to STATE_TRIP (3) 
at the exact moment PTT is asserted.

================================================================================
PART 1 - TARGETED DIAGNOSTIC (IMMEDIATE ACTION)
================================================================================
To stop guessing and follow the project rule ("measure the decision"), modify 
your MDB script (`tools/simulate/probe_q10_ptt_path.py`) to halt execution 
immediately after the state transitions to 3 (STATE_TRIP) and dump these exact 
internal registers to `q10_ptt_probe_mdb.log`:

    print g_state
    print g_trip_reason
    print ADRES
    print ADPCH
    print ADREF

This will immediately expose exactly WHICH protection circuit fired (via the 
bitmask of `g_trip_reason`) and which analog channel the ADC was examining.

================================================================================
PART 2 - THE ARCHITECTURAL CULPRITS (WHY PIC18 FAILS WHERE PIC16 PASSES)
================================================================================

SUSPECT 1: THE ADREF VOLTAGE REFERENCE SHIFT (MOST LIKELY)
---------------------------------------------------------
The simulator warning "W0223-ADC: ADC input voltage low. ADC output underflow" 
is the definitive smoking gun. 

* The Core Difference: The PIC18F47Q10 has a fundamentally distinct bit map for 
  its ADREF (ADC Voltage Reference Control Register) compared to the PIC16F18875.
* The Failure State: If your PIC16 initialization code performed a raw byte write 
  to ADREF, on the Q10 it may be accidentally selecting an unconfigured external 
  VREF+ pin or an un-enabled Fixed Voltage Reference (FVR) module instead of VDD.
* The Result: The ADC engine reference floats or drops to 0V. Any incoming voltage 
  causes a massive scaling underflow/overflow, driving software unit calculations 
  sky-high and instantly breaching the trip thresholds.
* The Fix: Explicitly force the Q10's ADC reference to VDD and VSS in your code:
    ADREFbits.ADNREF = 0;  // VREF- is connected to VSS
    ADREFbits.ADPREF = 0;  // VREF+ is connected to VDD

SUSPECT 2: 10-BIT RESULT SIGN EXTENSION / JUSTIFICATION (ADFM)
--------------------------------------------------------------
* The Core Difference: The Q10 uses an Advanced Analog-to-Digital Converter with 
  Computation (ADCC). 
* The Failure State: If your result formatting bit (ADFM) is misconfigured or handled 
  differently by the compiler headers between the families, reading the combined 
  10-bit value can shift bits internally. 
* The Result: A completely normal, safe reading (like a low baseline current draw) 
  is incorrectly interpreted as a massive over-threshold value (e.g., severe 
  overcurrent or drain peak voltage), immediately triggering a trip.

SUSPECT 3: UNINITIALIZED COMPILER RESETS ON EEPROM THRESHOLDS
-------------------------------------------------------------
* The Core Difference: The Q10 non-volatile memory (NVM) block requires an entirely 
  different driver layout than the PIC16.
* The Failure State: If your new Q10 NVM read code returns 0x00 or garbage data 
  because of a configuration offset, your trip thresholds load as zero.
* The Result: The condition `if (current_reading > trip_threshold)` evaluates to true 
  instantly because the chip is comparing against a threshold of 0.
* The Fix: Guard the threshold loading with safe fallback values during simulation:
    #ifdef __MPLAB_DEBUGGER_SIMULATOR__
        trip_threshold_current = 40;   // Force a known-safe threshold for MDB
        trip_threshold_overdrive = 100; 
    #endif
