TECHNICAL RESOLUTIONS FOR PIC18F47Q10 SIMULATION BLOCKERS
================================================================================
Date: 2026-09-22
Target Chip: PIC18F47Q10
Branch: upgrade/pic18f47q10

This document provides the complete root-cause analysis and actionable fixes 
for the two blockers identified during simulation testing in the MPLAB MDB environment.

================================================================================
BLOCKER 1: THE INFINITE STARTUP-INHIBIT LOOP (STATE_RESET_WAIT)
================================================================================

THE FAULT MECHANICS:
-------------------
The test script ran the simulation for 800,000 instruction steps, but noticed 
that 'g_startup_inhibit' remained trapped at true, and 'g_state' stayed locked in 
STATE_RESET_WAIT (5). This was interpreted as a permanent lockup.

However, this is a math illusion caused by the faster clock speed of the PIC18.

1. At 64 MHz, the PIC18F47Q10 runs at 16 MIPS (Million Instructions Per Second).
2. Each individual instruction cycle (TCY) takes exactly 62.5 nanoseconds.
3. Therefore, running 800,000 steps calculates as:
   800,000 steps * 62.5 ns = 0.050 seconds (exactly 50 milliseconds).

Because the firmware implements a hardcoded 1000 ms (1 second) settle delay before 
allowing PTT tracking, the firmware requires a total of 16,000,000 instruction 
steps to pass this window. The 50 ms simulation run simply cut off way too early.

RESOLUTIONS:
------------
Choose one of the two strategies below to resolve this in your test pipeline:

Strategy A: Adjust the MDB Script (Recommended for comprehensive testing)
Modify your MDB simulation macro to execute enough cycles to step clear of the 
1-second timing boundary:
    
    Stepi 16500000    <- Run ~1.03 seconds of simulated time to clear the gate

Strategy B: Implement a Conditional Software Bypass
If running 16 million steps slows down your local automation toolchain excessively, 
force the lock to drop immediately when compiling for the simulator:

    #ifdef __MPLAB_DEBUGGER_SIMULATOR__
        g_startup_inhibit = false; // Drop settle delay instantly in MDB
    #endif

BLOCKER 2: THE RA6 ANALOG SIGNAL OVERRIDE ANOMALY (OUTPUT_LCD_E)
================================================================================

THE FAULT MECHANICS:
-------------------
Even after explicitly setting '#pragma config CLKOUTEN = OFF', the simulator 
continues to report RA6 as an analogue pin, ignoring digital write stimulus. 

On the PIC18F47Q10, RA6 is multiplexed directly with the primary External 
Oscillator gate (OSC2). If the External Oscillator selection configuration bits 
(FEXTOSC) are unconfigured or active, the core hardware oscillator module takes 
absolute priority over the digital GPIO registers. To protect delicate high-frequency 
quartz crystals, the internal silicon completely isolates the digital buffers, 
which the MDB simulator flags as an "analogue state".

RESOLUTIONS:
------------
To fully release RA6 to function as a general-purpose digital output for your 
LCD enable strobe (OUTPUT_LCD_E), apply the following configuration fixes:

1. Update your configuration bits to explicitly turn OFF the external oscillator 
   and configure the internal HFINTOSC to drive the chip at full 64 MHz:

    #pragma config FEXTOSC = OFF        // Turn off external crystal hardware
    #pragma config RSTOSC = HFINTOSC_64MHZ // Set internal clock natively to 64 MHz

2. Ensure your port initialization explicitly clears the analog selection flag 
   for bit 6 (which is frequently overlooked when dealing with Port A):

    TRISAbits.TRISA6 = 0;    // Configure pin as an output
    ANSELAbits.ANSELA6 = 0;  // Force pin to digital mode (kill analog override)
