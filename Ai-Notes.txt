## Current design
This repository is the active PIC16F18855-I/SP linear-amplifier protection controller. Obsolete prototype source files have been removed so they cannot enter the production build.

## Firmware
- Direct ADC inputs monitor two forward/reflected SWR pairs, temperature, WCS1700 current, input power, and drain voltage.
- SWR trips, power scales, drain/input thresholds, 10 kOhm NTC B-value profile, sequencer timing, and output polarities are user-configurable from the 1602 LCD menu.
- Hardware comparators combine at INPUT_HARD_FAULT for independent overdrive, drain-peak, and overcurrent protection.
- The sequencer runs TX, TX_VCC, and TX_BIAS with two configurable inter-stage delays, defaulting to 20 ms.
- The LCD uses a PCF8574 backpack driven with software I2C on RC3/RC4 by firmware/src/lcd_i2c.c.
- Menu settings and the last display page are stored in the PIC's internal EEPROM in a versioned, checksummed record; no external EEPROM module is used.

## Display
- The default status page shows post-filter forward power as PEP or RMS and a full-width `-`/`.` PEP bar.
- A second status page shows a PEP bar with temperature in degrees C.
- PEP decay is user-configurable and defaults to 500 ms.

## CI / release
- .github/workflows/firmware-build.yml builds on every push/PR to main on a self-hosted Windows runner (XC8 + Ninja) and packages `.hex`/`.elf`/`.map`/`.xml` plus the hardware netlist (docs/hardware/schematic/PicAmpControl.net) and pin map (docs/hardware/PIC16F18855_pin_map.md) into a `firmware-<sha>` artifact.
- .github/workflows/auto-release.yml runs after a successful main build, auto-increments a `v0.0.N` tag, and publishes that artifact as a GitHub Release. This is fully automatic - no manual step needed for a normal push to main.
- .github/workflows/release-firmware.yml is the manual fallback (workflow_dispatch) to re-publish an older build's artifact under an existing tag.

## Device memory usage
- `memoryfile.xml` (and `mem.map`) is regenerated by XC8 on every build and is always included in the latest release, so it always reflects the current firmware, not a stale snapshot.
- To check current % free: download it from the latest release (`gh release download <tag> -p memoryfile.xml`) and read `<memory name="program">`/`<memory name="data">` `used`/`free`/`length` (program = flash words, data = RAM bytes).
- As of v0.0.25 (commit 3a49285): program flash 54.2% free (4440/8192 words), data RAM 84.2% free (862/1024 bytes).
