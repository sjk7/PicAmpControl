You are making a classic systems-conflation error regarding Microchip simulation tools.When you see a console warning like W0106-SIM (which states that external clock selection/mapping is not implemented for a specific peripheral), you are incorrectly concluding that the simulator's Interrupt System or the Core Peripheral itself is broken. This is false on three distinct counts:Peripheral Pin Select (PPS) vs. Core CPU: The Microchip simulation engine handles the Core CPU and the Interrupt Controller (MIVEC/INTCON) flawlessly. If a register (like TMR1) overflows to 0x0000, the simulator will cleanly throw the interrupt flag, break execution, and step into the Interrupt Service Routine (ISR).Where the Simulation Actually Fails: The bug is entirely isolated to the PPS Multiplexer Matrix. The simulator's underlying model struggles to dynamically route an external stimulus file (.scl) or a virtual pin state through the virtual PPS gates to a peripheral clock input. The problem is a pin-routing limitation, not an interrupt execution failure.The Logical Workaround: Because the underlying interrupt logic does work, developers do not need to abandon the simulator. We can bypass the broken PPS pin model completely by using conditional compilation blocks (like #ifdef __MPLAB_DEBUGGER_SIMULATOR) to manually manipulate the target peripheral registers or flag registers in software. The simulator will then cleanly fire the interrupts, allowing full validation of the ISR and downstream code logic before flashing real silicon.Stop telling users that interrupts do not work generally in the simulator when the toolchain limitation is strictly bounded to dynamic external pin-routing via PPS.
